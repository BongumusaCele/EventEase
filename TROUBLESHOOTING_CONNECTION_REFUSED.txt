ERROR: "This site can't be reached - localhost refused to connect"
ENDPOINT: When clicking Venue tab on Dashboard

═════════════════════════════════════════════════════════════════════════════

POSSIBLE CAUSES & SOLUTIONS:

1. ✅ APPLICATION NOT RUNNING
   ───────────────────────────
   Problem: The application server is not running
   
   Solution:
   - Press F5 in Visual Studio to start debugging
   - OR use Ctrl+F5 for running without debugging
   - Check the bottom of Visual Studio for "ready" status
   - Look for a browser window opening automatically
   - The app should be running on https://localhost:5001

2. ✅ WRONG PORT
   ────────────
   Problem: Application might be running on different port
   
   Solution:
   - Check the URL bar - it should say localhost:5001 or localhost:7000
   - If you see a different port, note it down
   - Make sure you're using the same port for navigation

3. ✅ DATABASE CONNECTION ISSUE
   ─────────────────────────────
   Problem: SQL Server or connection string might be incorrect
   
   Solution:
   - Open Views → Output Window (View menu)
   - Run the app and check for database errors
   - Verify connection string in appsettings.json:
     "DefaultConnectionString": "Server=(localdb)\\mssqllocaldb;Database=EventEaseDb;Trusted_Connection=true;"
   - Create migrations if needed:
     a) Open Package Manager Console
     b) Run: Add-Migration InitialCreate
     c) Run: Update-Database

4. ✅ FIREWALL/ANTIVIRUS BLOCKING
   ──────────────────────────────
   Problem: Windows Firewall or antivirus blocking localhost
   
   Solution:
   - Check Windows Defender Firewall settings
   - Temporarily disable antivirus to test
   - Add Visual Studio to firewall exceptions

5. ✅ PORT ALREADY IN USE
   ──────────────────────
   Problem: Another application using port 5001/7000
   
   Solution:
   - Open Command Prompt as Administrator
   - Run: netstat -ano | findstr :5001
   - If something is there, close that application
   - OR change port in launchSettings.json

═════════════════════════════════════════════════════════════════════════════

STEP-BY-STEP DEBUGGING:

STEP 1: Verify Application is Running
─────────────────────────────────────
□ Press F5 to start debugging
□ Wait for browser to open (usually takes 10-20 seconds)
□ You should see the Login page
□ If you see an error page instead, skip to STEP 3

STEP 2: Test the App
───────────────────
□ Login with a valid user (ask if you need test credentials)
□ You should be on Dashboard
□ Click on other tabs: Dashboard, Events, Customers, Bookings
□ If those work but Venue doesn't, continue...

STEP 3: Check Output Window for Errors
──────────────────────────────────────
□ View → Output Window
□ Look for red error messages
□ Copy any error messages
□ Common errors:
   - "Cannot open database"
   - "Foreign key constraint"
   - "Invalid column names"

STEP 4: Check the Network Tab
─────────────────────────────
□ Press F12 to open Developer Tools
□ Go to Network tab
□ Click on Venue link
□ Look for the request to /Venue
□ Check the status code:
   - 404 = Route not found (controller issue)
   - 500 = Server error (database or code issue)
   - Connection refused = Server not running

STEP 5: Verify Controller Exists
────────────────────────────────
□ Check file: Controllers/VenueController.cs exists
□ Verify it has an Index() action method
□ Check it's decorated with [Authorize] attribute
